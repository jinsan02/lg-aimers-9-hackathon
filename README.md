# LG Aimers 9기 — 투구 제구 성공 확률 예측

[DACON 대회 링크](https://dacon.io/competitions/official/236743)

투구가 던져지기 **전에** 확보 가능한 정보만으로 그 투구의 제구 성공 확률을
0~1 실수로 예측합니다. 실패는 ① 스트라이크존 한가운데 ② 존 이탈
③ 포수 요구와 반대 방향의 세 가지로 정의됩니다.

정답을 맞히는 문제가 아니라 **확률을 잘 보정하는 문제**입니다. 0/1로 반올림하면
점수가 붕괴합니다.

```
score = max(0, 100000 × (1 − brier / (r(1−r))))     r = 비공개 실제 성공률
```

## 가장 큰 레버 — `asof_*`는 시즌 리셋 없는 통산 누적이다 (+72.6)

순위표에서 역산해 찾았습니다. 상위권 점수를 로컬 좌표로 환산하면 약 1,000인데,
자체 신호 감사에서 **「투수 정체성만 알 때」의 상한이 990.8**이었습니다. 즉
상위권은 각 투수의 **당해 시즌** 실력을 알고 있다는 뜻인데, 평가 시즌(2025)
성적은 주어지지 않습니다.

열쇠는 제공된 `asof_*` 19개 컬럼이 **시즌마다 리셋되지 않는 통산 누적**이라는
점이었습니다 (투수-시즌 1,468건 전수 검사: 리셋 비율 0.000).

```
S  = asof_pitcher_n × asof_pitcher_success_rate          # 통산 성공 횟수
당해 시즌 성적 = (S − S₀) / (n − n₀)                      # (n₀, S₀) = 직전 시즌 말 상태
```

앵커 `(n₀, S₀)`는 **train만으로** 만들고 나머지는 **그 행 자신의 컬럼**이므로
행 독립 원칙을 지킵니다. 통산 성공률은 자동 볼판정(ABS) 이전 구체제에 오염돼
있는데, 차분하면 현 체제 성적만 남는 것이 두 번째 이득입니다.

**효과 +72.64 (t=12.2, 3시드 페어드).** A100 별도 풀에서 +72.63 재현,
XGBoost 계열도 754 → 830으로 함께 상승했습니다. 구현은 `src/season_std.py`.

누수 검증 6항목(앵커가 미래를 참조하지 않는지, 시즌 첫 투구 행의 값이
사전확률 하나뿐인지 등) 전부 통과했습니다.

## 아키텍처

서로 다른 출력 기하를 가진 두 계열을 **고정 가중 0.45 / 0.55**로 결합합니다.

```
base 팔 (0.45)   CatBoost 이진 Logloss, depth 8, 121 피처, 8시드
cell 팔 (0.55)   CatBoost 12-클래스 MultiClass, depth 5, 123 피처, 6시드
                 P(성공) = 성공 셀 [9,10,11] 확률의 합
```

`cell` 팔은 실패 모드(middle / ball / reverse)를 보조 감독 신호로 쓰는
12-셀 분류입니다. 성공 비트의 의미는 정확히 보존됩니다.

추론 순서 (이 순서가 레시피의 일부):

```
1. 가중 평균                p = 0.45·mean(base) + 0.55·mean(cell 성공셀 합)
2. 전역 캘리브레이션         p = sigmoid(1.0416 · logit(p)) ;  p = clip(p − 0.0052)
3. 최근 한가운데 구간 오프셋  (그 행 자신의 컬럼만 읽음)
4. 투수×타자 매치업 오프셋    (그 행의 두 ID만 읽음)
5. p = clip(p + 0.002515795361)
```

## 행 독립성 — 다수가 실격당한 지점

주최측은 2026-08-13에 다수 실격 후 규정을 재공지했습니다.

> 한 행의 예측은 `test.csv`에 그 행만 있을 때와 전체 평가셋이 있을 때가
> **동일해야 한다.**

**행 순서를 뒤집는 검사로는 부족합니다.** groupby 평균·전역 분위수·빈도 카운트는
모두 순서 불변이라 뒤집기 검사를 통과하면서 여전히 실격 사유입니다. *어떤 행이
존재하는지*를 바꿔야 잡힙니다.

그래서 **절반 / 특정 선수만 / 흩어진 부분집합 / 진짜 1행 / 역순** 다섯 가지로
드리프트를 재는 감사를 만들어 패키징에 강제로 물렸습니다.
최종 제출본은 다섯 검사 전부 **드리프트 `0.000e+00`** 입니다.

> ⚠️ `src/failmode.py`는 **학습 전용**입니다. 같은 알고리즘을 평가 데이터에
> 적용하면 2025 타깃의 **96.79%가 복원**됩니다. 감독 라벨만 만들고 피처는 만들지
> 않으므로 학습에는 정당하지만 제출 패키지에 들어가면 실격입니다.
> 패키징 시 이 파일의 부재와 행간 차분(`.diff`) 0건을 매번 검사합니다.

## 검증 체계

점수보다 **판정 규칙**에 더 공을 들인 저장소입니다.

- **채택 규칙을 코드 한 파일로 고정** (`tools/judge.py`)
  `Δ ≥ +3 AND t ≥ 2.4 AND n ≥ 6 페어드 AND 같은 머신 AND 같은 표면`
  그 전에는 두 판정 도구가 n=6에서 각각 1.96과 2.571을 쓰며 같은 증거를 다르게
  판정하고 있었습니다.
- **사전등록** — 모든 GPU 실험 전에 가설·변수·명령어·성공/실패 규칙을 문서로
  커밋. 「큰 음수를 미리 수용한다」를 명시해 결과를 재해석하지 않습니다.
- **매칭 귀무분포** — 무작위 방향조차 챔피언 잔차와 |ρ| 중앙값 0.0035~0.0058로
  상관합니다. +3점 문턱이 ρ=0.0055이므로, **귀무 중앙값 이하의 ρ는 증거가
  아닙니다.**
- **머신 효과** — 동일 설정·동일 시드가 4070에서 +4.27, A100에서 +10.31.
  교차 머신 절대 점수 비교 금지, 같은 세션 fresh control만 사용.
- **리더보드 해상도** — 델타의 표집 표준오차 ±1.06. 이 계산으로 블렌드 가중
  탐색 제출 2회를 취소했습니다(이득 +0.07, 신호대잡음 0.066).

`docs/SETTLED.md`에 판정·수치·기전을 한 줄로 남기는 append-only 규칙으로
**202개 축**을 닫았습니다 (CLOSED 96 / FAIL 16 / BANNED 14 / DROP 12 / PARK 4 …).
음성 결과를 지우지 않는 이유는 같은 축이 이름만 바꿔 돌아오는 것을 막고,
`tools/precheck.py`가 실행 전에 자동 대조하기 위해서입니다.

대표적인 기각:

| 축 | 결과 |
|---|---|
| 실패 모드 감독 **삭제** | **−18.581** — 채점이 못 보는 정보에 상호정보 7.4배를 쓰는데도 없애면 손해 |
| 2022 이전 F리그 행 제거 | **−61.008**, 라벨 문제 없는 R리그도 −51.23 (공유 테이블이 함께 잘림) |
| 시즌 재가중 | 최악 시즌을 올려도 −84.14, 내려도 −80.04 — **방향이 아니라 재가중 자체가 비용** |
| 셀 팔 leaf 수렴 정렬 | 셀 단독 **+2.579**인데 코어 **−0.381** — 두 팔이 가까워져 앙상블 다양성을 소모 |
| 셀 팔 반복 상한 해제 | 코어 −1.056 — 상한은 결함이 아니라 **암묵적 정규화**였음 |

## 실행

대회 데이터는 재배포할 수 없으므로 `data/`를 직접 채워야 합니다.

```bash
# 실행 전 중복·금지 플래그 검사 — "N command(s) checked" 줄이 없으면 검사 안 된 것
python tools/precheck.py --file scripts/<script>.bat

# 학습 (제출 표면, base 팔)
python src/train_gbdt2.py \
  --model cat --feat-v2 --feat-k 200 --te p,pc,ph,b,pi --te-k 50 --te-dev \
  --feat-std --std-k 80 --std-to-prior --std-season-prior \
  --feat-domain --feat-skill-pc \
  --lr 0.01 --iters 3000 --es 500 --l2 10 --border-count 254 \
  --loss Logloss --eval-metric Logloss --refit-mult 1.5 --p1 \
  --val-season 2024 --max-train-season 2024 \
  --depth 8 --seeds 3,4,5,6,8,13,42,7 --tag B1S_base

# cell 팔은 위에 추가
#   --feat-skill --depth 5 --failmode-cells \
#   --fm-modes middle,ball,reverse --fm-min-share 0.005 --seeds 3,4,5,6,8,13

# 패키징 + 감사
python tools/build_submission.py --tag <TAG> --out submissions/<name>.zip
python tools/audit_subset_independence.py --package <unzipped>

# 회귀 테스트
python tests/run_all.py      # 27/27
```
