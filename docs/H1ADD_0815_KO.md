# H1ADD 실험 결과와 팀원 공유 사항 (2026-08-16 LB 반영)

## 1. 결론부터

이번 변경은 팀원의 B1S8에서 **이진 base 모델에 피처 한 개만 추가**한 실험이다.
기존 121개 피처는 모두 유지하고 `h1_hand_delta`를 더해 122개로 만들었다.

- 같은 Mac CPU에서 새로 학습한 B1S base 대조군과 비교하면 로컬 BSS가 올랐다.
  - 8시드 중심화 앙상블: `924.0884 -> 929.5908`, **+5.5024 BSS**
  - 8시드 대응 차이 평균: **+4.9952 BSS**
  - 표준오차 2.0497, t=2.4370, 95% 신뢰구간 `[+0.1484, +9.8420]`
- 이 결과로 Mac 로컬의 사전 기준 `평균 +3 이상, t 2.4 이상`은 통과했다.
- 실제 DACON 제출 결과는 **1111.67304점**이었다.
  - 팀원 B1S8: `1108.4333490288`
  - H1ADD base-only 제출본: `1111.67304`
  - 실제 LB 상승: **+3.2396909712점**
- 따라서 **팀원의 B1S8보다 실제 대회 점수가 높아졌다는 사실이 확인됐다.**
- 팀원이 최신 `main`에서 RTX 5070으로 실시한 6시드 base+cell 전체 변경 실험은
  core -0.304였지만, 이번 제출본은 H1ADD를 base 8개에만 적용하고 cell 6개는
  B1S8 그대로 유지했다. 두 실험은 변경 범위가 다르므로 모순되는 결과가 아니다.

이 문서는 실제 LB 상승을 최우선 증거로 반영하고, 어느 구간에서 개선 신호가
나왔는지와 그 이유에 대한 추정을 관측 사실과 분리해 기록한다.

## 2. 팀원의 B1S8에서 정확히 무엇을 바꿨나

팀원 B1S8의 주요 구성은 다음과 같다.

- 이진 base CatBoost 8개: depth 8, seeds `3,4,5,6,8,13,42,7`
- failure-mode cell CatBoost 6개: depth 5, seeds `3,4,5,6,8,13`
- base/cell 확률 블렌드 가중치: `0.45 / 0.55`
- 공통 피처 121개
- 후처리: slope 1.0416, shift 0.0052, recent-middle 보정,
  고정 pitcher×batter 보정

H1ADD는 다음 한 가지만 바꿨다.

```text
B1S base: 121개 피처
H1ADD:    기존 121개 + h1_hand_delta = 122개 피처
```

기존 H1 replacement 실험과 달리
`std_asof_pitcher_success_rate_delta`를 삭제하지 않았다. 그래서 이번 실험은
기존 피처 제거 효과와 새 피처 추가 효과가 섞이지 않는다.

`h1_hand_delta`는 아래 정보를 결합한, 당해 시즌 표본 수에 따라 수축되는
투수-타자 손 조합 보정치다.

```text
손 조합 편향 = 투수의 상대 타자 손별 TE 편차
개인화 사전확률 = clip(시즌 사전확률 × 손 조합 편향, 0, 1)
h1_hand_delta = (개인화 사전확률 - 시즌 사전확률)
                × 80 / (당해 시즌 투수 표본 수 + 80)
```

야구적으로는 같은 투수라도 좌·우 타자를 상대할 때 릴리스 방향, 공의 횡 무브먼트,
포수의 요구 코스와 승부 방식이 달라진다는 점을 반영한다. 이 수식은 당해 시즌
표본이 적은 초반에는 과거 자료에서 얻은 손 상대 사전 보정을 더 강하게 사용하고,
당해 시즌 관측이 쌓일수록 그 보정을 줄여 현재 시즌 성공률 피처가 더 큰 역할을
하도록 한다. 현재 투구 이후 정보나 다른 테스트 행의 통계는 사용하지 않는다.

## 4. 팀원의 최신 5070 결과와 왜 모순되지 않는가

최신 `main`의 근거는 커밋 `77d4b09c1de70e7397d4e278532e1cebacf68e31`과
`docs/SETTLED.md`의 `H1_ADDITIVE` 항목이다.

| 비교 | 결과 |
|---|---:|
| fresh-vs-fresh 전체 core | -0.304 BSS |
| base arm | +2.161 BSS |
| cell arm | -1.235 BSS |
| core 95% 신뢰구간 | [-3.25, +2.64] |

두 결과가 다른 핵심 이유는 다음과 같다.

1. Mac 실험은 **base-only 8시드** 비교다. 팀 GPU 실험은 base와 cell을 모두
   H1ADD로 바꾼 **6시드 전체 core** 비교다.
2. 학습 머신이 다르다. 이 저장소는 같은 설정도 머신이 달라지면 BSS가 크게
   달라진 사례가 있어 절대 점수를 머신 사이에서 직접 비교하지 않는다.
3. Mac 판정은 시드별 중심화 비교가 주 근거다. 팀 판정은 같은 세션의 fresh
   control과 실제 base/cell 블렌드를 주 근거로 쓴다.
4. 최신 GPU 재학습에서 base 조기종료 지점이 시드별로 크게 움직였다.
   평균 절대 변화가 255.8회였고 seed 5는 712회 차이가 났다. 이 때문에 base
   효과의 표준오차가 2.346으로 커졌다.

따라서 Mac 결과는 “이 피처를 base에만 넣었을 때 가능성이 있었다”는 증거이고,
팀 GPU 결과는 “base와 cell을 모두 H1ADD로 교체하면 전체 B1S8을 이기지 못했다”는
판정이다. 실제 제출은 Mac에서 검증한 **base-only 구성**을 사용했고 LB가
+3.23969 올랐다. 특히 GPU 실험에서도 base는 +2.161, cell은 -1.235로 방향이
갈렸으므로, 음수였던 cell을 그대로 둔 제출 설계가 실제 상승과 일치한다.

## 6. 어느 구간에서 성능이 올랐나

숨은 평가 데이터의 행별 정답은 공개되지 않으므로 실제 평가 구간별 점수를 직접
분해할 수는 없다. 아래는 저장된 2024 검증 253,507행에서 B0와 H1ADD의 **base-only
8시드 앙상블**을 정확히 재생한 결과다. 최종 base/cell 블렌드의 구간별 분해가
아니다. 각 기여도는 base-only 중심화 BSS +5.5024에 합산되는 형태로 계산했으며,
양수는 H1ADD base가 B0 base보다 MSE를 줄였다는 뜻이다.

### 6.1 손 조합과 경기 유형 코드

| 구간 | 행 수 | 전체 BSS 개선 기여 | 전체 개선 중 비중 |
|---|---:|---:|---:|
| same-hand | 122,902 | **+4.6310** | **84.2%** |
| opposite-hand | 130,605 | +0.8714 | 15.8% |
| R 코드 전체 | 223,497 | **+5.4217** | **98.5%** |
| F 코드 전체 | 30,010 | +0.0807 | 1.5% |
| R × same-hand | 105,388 | **+4.4914** | **81.6%** |
| R × opposite-hand | 118,109 | +0.9303 | 16.9% |
| F × same-hand | 17,514 | +0.1396 | 2.5% |
| F × opposite-hand | 12,496 | -0.0589 | -1.1% |

가장 뚜렷한 신호는 `R × same-hand`다. H1 피처 자체도 same-hand에서 평균
`-0.001782`, opposite-hand에서 `+0.001432`로 반대 방향을 갖는다. 단순한
same/opposite 플래그가 아니라 투수별 손 상대 TE 편차의 방향과 크기를 제공하기
때문에, 기존 플래툰 피처가 표현하지 못한 투수별 차이를 트리가 사용할 수 있었다고
추정한다.

손 코드 조합별 기여는 `1/1 +2.2245`, `2/2 +2.4065`, `1/2 +1.0950`,
`2/1 -0.2236`이었다. 공식 문서에서 코드 1/2의 좌·우 매핑을 확정하지 않았으므로
코드 그대로 적는다.

### 6.2 당해 시즌 투수 경험도

| `std_pitcher_n` | 행 수 | 전체 BSS 개선 기여 | 전체 개선 중 비중 |
|---|---:|---:|---:|
| 0 | 81 | -0.0056 | -0.1% |
| 1~49 | 17,992 | +0.0910 | 1.7% |
| 50~199 | 43,074 | -0.4135 | -7.5% |
| 200~499 | 64,395 | **+1.7994** | **32.7%** |
| 500 이상 | 127,965 | **+4.0311** | **73.3%** |

양의 기여가 100%를 넘는 것은 50~199 구간의 손실을 다른 구간이 상쇄했기 때문이다.
H1 수식은 표본 수가 커질수록 값 자체를 축소하지만, 경험 많은 투수의 손 상대 TE가
더 안정적이고 기존 성공률 피처와 함께 해석될 수 있어 실제 이득은 200구 이상에서
집중됐다. “표본이 적을 때 크게 움직이므로 유리했다”는 설명은 데이터와 맞지 않는다.

### 6.3 카운트·주자·이닝

- 카운트 기여 상위: `0-1 +1.8163`, `1-0 +1.2973`, `1-1 +1.1778`,
  `3-2 +0.7251`, `2-0 +0.5944`, `1-2 +0.5829`
- 손실 구간: `0-2 -0.5391`, `3-1 -0.3062`, `2-2 -0.0147`
- 주자 없음: `+2.6851`, 주자 1명: **`+4.0788`**, 주자 2명: `-1.3351`,
  만루: `+0.0736`
- 1~3회: **`+4.3196`**, 4~6회: `+1.9776`, 7~9회: `-0.6563`,
  연장: `-0.1384`

이는 H1이 모든 상황에서 균일하게 좋아진 것이 아니라, 투수가 비교적 계획된 승부를
하는 초·중반과 주자 0~1명, 일부 카운트에서 더 잘 작동했음을 시사한다. 반대로
후반·주자 2명·일부 투스트라이크 구간에서는 경기 상황과 불펜 운용의 영향이 커져
투수의 장기 손 상대 성향만으로는 부족했을 가능성이 있다. 이 해석은 가설이며,
구간들은 서로 중첩되므로 각 수치를 독립적으로 더하면 안 된다.

## 7. 모델이 실제로 H1 피처를 사용했나

사용했다. 단순히 피처를 추가했지만 트리가 무시한 결과가 아니다.

- 최종 전체 재학습 base 모델 8개에서 `h1_hand_delta`의 CatBoost
  PredictionValuesChange 순위는 모두 **7~8위**, 평균 중요도는 **1.7517**이었다.
- 정직한 2019~2023 학습 / 2024 검증 모델 seed 3의 20,000행 SHAP에서
  `h1_hand_delta`는 **122개 중 5위**, mean|SHAP| `0.01786`이었다.
- 같은 SHAP에서 mean|SHAP|은 same-hand `0.02184`, opposite-hand `0.01416`으로
  same-hand에서 약 54% 컸다.
- H1 값과 자신의 SHAP 값 상관은 `+0.602`였다. 값의 방향과 모델 기여 방향이
  상당히 연결돼 있었다.
- H1 값은 `te_pitcher_batter_hand_ratio_dev`와 상관 `+0.762`로 높았다.
  기존 `std_asof_pitcher_success_rate_delta`와의 상관은 `+0.125`에 그쳐,
  기존 delta를 삭제하지 않고 둘을 함께 둔 것이 서로 다른 정보를 보존했다.
- 대표 모델의 주요 상호작용 상대는
  `std_asof_pitcher_success_rate`, 팀 ID, `std_asof_batter_success_rate`,
  `season`, `dom_same_rev`, `dom_same_ball`, `strikes_before`였다.

SHAP은 raw logit 기여이고 BSS나 인과효과가 아니다. 또한 H1과 손 TE의 상관이 높아
개별 중요도는 서로 나뉠 수 있다. 여기서는 “모델이 H1을 강하게 사용했다”는 증거로만
해석한다.

## 8. 왜 실제 LB가 올랐다고 추정하는가

관측 증거를 종합하면 가장 가능성 높은 설명은 다음과 같다.

1. **기존 정보를 버리지 않았다.** replacement H1은 기존 pitcher-success delta를
   삭제했지만 H1ADD는 이를 유지했다. 기존의 전체 제구 수준과 손 상대 특수성을
   동시에 사용할 수 있었다.
2. **base 모델에만 적용했다.** 팀 GPU 실험에서도 base는 +2.161, cell은 -1.235였다.
   실제 제출은 음수였던 cell을 B1S8 그대로 두고 base만 교체했다.
3. **투수별 손 상대 차이를 비선형적으로 조합했다.** CatBoost가 원재료 TE를 이미
   갖고 있어도, 시즌 사전확률과 표본 수를 결합한 H1 값을 직접 제공하면 제한된
   트리 깊이 안에서 더 쉽게 활용할 수 있다.
4. **same-hand·R 코드·경험 많은 투수의 비중이 충분했다.** 2024 검증 이득의
   대부분이 이 구간에서 나왔다. 숨은 평가 데이터에도 유사한 구성이 충분히 존재해
   신호가 전이됐을 가능성이 높다.
5. **전역 평균 이동보다 구분력 개선이 중심이었다.** 후보 예측 평균은 B0보다
   `+0.000270` 높아졌고, raw 앙상블 개선은 +3.8886, 평균 편향을 제거한 개선은
   +5.5024였다. 후보가 평균 보정을 잘해서 오른 것이 아니라 행별 상대 위험도를
   더 잘 나눈 뒤 일부 전역 편향 비용을 지불한 형태다. 실제 LB +3.2397이 raw
   로컬 개선과 같은 방향이라는 점도 이 설명과 부합한다.

투수 단위 20,000회 부트스트랩에서는 중심화 개선이 양수일 확률이 94.7%였지만
95% 구간은 `[-1.18, +11.96]`로 0을 포함했다. 투수의 49.9%만 합산 손실이
개선됐고, 상위 10명 기여 `+5.06`과 하위 10명 `-4.38`이 크게 상쇄됐다.
따라서 모든 투수에게 좋아진 보편 법칙이 아니라, 적합한 투수·상황에서 얻은 작은
확률 개선이 전체 LB를 +3.24 올린 것으로 보는 것이 안전하다.

## 9. 확정할 수 없는 부분

- 숨은 평가 데이터의 행별 타깃과 세그먼트 구성을 받지 못했으므로 실제 LB
  +3.23969가 어느 선수·손 조합·카운트에서 발생했는지는 직접 증명할 수 없다.
- 최종 base 모델은 H1 추가 후 다시 학습됐으므로, 조기종료 반복 수와 트리 구조도
  함께 바뀌었다. H1은 유일한 의도적 설정 변경이지만 점수 전부를 단일 수식의
  순수 인과효과라고 단정할 수는 없다.
- 2024 세그먼트 분석과 실제 LB의 방향 일치는 강한 간접 근거지만, 다음 시즌이나
  다른 선수 구성에서 동일한 +3.24를 보장하지 않는다.
- 이번 LB 결과는 base-only 제출 설계를 채택할 근거다. 계수 80, 손 구간 게이트,
  카운트별 보정 등을 LB를 보고 추가 탐색하면 정답 피팅이 되므로 하면 안 된다.

## 10. 학습과 검증에 사용한 파일

`0815` 브랜치에는 최신 팀 코드 기준으로 다음 파일이 포함돼 있다.

- `src/fpipe.py`: H1 피처 생성과 additive/replacement 분기
- `src/train_gbdt2.py`: `--feat-h1`, `--h1-additive` 학습 인자와 모델 학습
- `tests/test_h1_additive.py`: 기존 delta 유지, 121→122 피처, 행 독립성 검증
- `scripts/chain_h1add_5070.bat`: 팀원의 5070 fresh-control 재학습 명령
- `tools/arm_compare.py`: base/cell/core 대응 비교와 통계 판정
- `docs/lineage/h1add_mac_base8_0815.json`: Mac 로컬 결과와 전체 재학습 요약
- `docs/H1ADD_0815_학습파일.txt`: 파일별 역할과 SHA-256 목록

로컬 Mac에서 실제 사용한 소스 묶음의 SHA-256은
`9b01cd8543461aeada291ec142e04033a53877cd081fb95370429b213ebdaef2`다.
최신 `main`은 이후 다른 실험과 감사 코드가 추가되었으므로 파일 자체 해시는 달라졌지만,
H1 additive의 핵심 수식과 121→122 계약은 같은 구현이다.

## 11. 팀원에게 전달할 한 문장

> B1S8의 기존 base 121개 피처는 하나도 빼지 않고, 투수의 좌·우 타자 상대 성향을
> 당해 시즌 표본 수로 수축한 `h1_hand_delta` 한 개만 추가했습니다. 같은 Mac CPU의
> 8시드 base-only 비교에서 앙상블 BSS가 +5.502 올랐고, 실제 제출도
> **1108.43335에서 1111.67304로 +3.23969 상승**했습니다. 2024 검증에서는
> same-hand, R 코드, 당해 시즌 200구 이상 투수 구간이 이득의 대부분을 만들었습니다.
> 최신 5070의 base+cell 동시 변경은 cell 손실 때문에 DROP이었으므로, cell을 유지하고
> base만 H1ADD로 교체한 것이 이번 제출의 핵심 차이입니다.
