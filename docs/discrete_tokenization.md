# 이산 토큰화(컬럼별 bin) — LLM 전환 가능성 탐구 (2026-08-05)

> 아이디어 출처: 사용자 제안 — "컬럼명:{셀값} 형태로 컬럼마다 범위를 조사해서 토큰화"
> 결론: **이 방향은 유효합니다.** 앞선 LLM 기각 사유(수치 토크나이저 파괴)를 정면으로 우회하고,
> 토큰 예산도 6.5배 줄어 시간 제약을 통과합니다. 다만 "사전학습 LLM"이 아니라
> "이산 토큰 + 트랜스포머"로 형태가 바뀝니다.

## 1. 왜 이게 앞선 기각을 뒤집는가

[llm_serialization_handoff.md](llm_serialization_handoff.md) §3의 기각 사유는
**BPE가 `5000`을 `50`+`00`으로 쪼개 수의 크기 관계를 파괴**한다는 것이었습니다.

이산 토큰화는 그 단계를 **아예 제거**합니다. `li=1.42` 를 텍스트로 쓰지 않고,
`li` 컬럼의 32분위 중 24번째 bin → **토큰 ID 하나**로 직접 매핑합니다.
숫자가 문자열을 거치지 않으므로 쪼개질 일이 없고, bin 임베딩이 학습되면서
순서 관계는 데이터로부터 복원됩니다.

## 2. 실측 — 우리 데이터의 토큰 예산 ([tools/column_profile.py](../tools/column_profile.py))

| 방식 | 행당 토큰 | 0.5B L4 소요 | 0.1B L4 소요 |
|---|---|---|---|
| 텍스트 직렬화 (47피처 풀네임) | 304 | ~33분 ❌ | ~7분 |
| 텍스트 직렬화 (키 약어) | 140 | ~14분 ❌ | ~3.4분 |
| **이산 토큰 (컬럼 순서 고정)** | **47** | **~5분 ✅** | **~1.2분 ✅** |

**컬럼 순서를 고정하면 컬럼명 토큰이 아예 필요 없습니다** — 위치가 곧 컬럼입니다.
47개 값 토큰만 남고, 이는 텍스트 방식 대비 **6.5배 압축**입니다.

### 어휘 설계 (실측 카디널리티 기준)

| 그룹 | 컬럼 수 | 필요 토큰 |
|---|---|---|
| 범주형·저카디널리티 (`top_bottom`, `base_state`, 카운트, 주자 등) | 16 | 그대로 값 개수 |
| 연속형 (32분위 이산화: `li`, `win_expectancy`, `asof_*` 등) | 31 | 컬럼당 ≤32 |
| **합계 (ID 제외)** | **47** | **956** |
| `pitcher_id` / `batter_id` 전용 토큰 추가 시 | | +792 / +830 |

어휘 956개(ID 포함 2,578)는 매우 작습니다 — 일반 LLM 어휘(32k~128k)의 3% 미만.
**즉 사전학습 임베딩 테이블을 거의 못 씁니다**(§4 참조).

## 3. 문헌 근거 — 이 기법은 이미 검증돼 있습니다

- **[Discrete Tokenization Unlocks Transformers for Calibrated Tabular Forecasting](https://arxiv.org/abs/2603.07448)** (2026)
  — "의도적으로 단순한 이산 어휘"만으로도 attention이 tabular에서 작동. 500만 학습 예제에서
  **튜닝된 XGBoost를 10.8% 상회**. 무엇보다 **캘리브레이션된 확률분포**를 출력.
  → 우리 과제는 Brier(캘리브레이션 지배)이고, E27에서 손실의 20.9점이 전역 편향이었음. 정확히 맞는 축.
- [Binning as a Pretext Task](https://arxiv.org/pdf/2405.07414) / [Adaptive Binning](https://arxiv.org/html/2606.19827) (2026)
  — 이산화를 자기지도 사전학습 과제로 사용
- [TabGemma](https://arxiv.org/pdf/2511.03570) — 직렬화 + 계속사전학습 + 검색 결합
- [LLM Embeddings for Deep Learning on Tabular Data](https://arxiv.org/pdf/2502.11596)

## 4. ⚠️ 정직한 반론 — "그러면 그건 LLM이 아니다"

어휘를 우리 bin 토큰으로 갈아끼우면 **사전학습된 임베딩 테이블이 무용지물**이 됩니다.
남는 건 트랜스포머 **본체(attention/FFN) 가중치**뿐인데, 언어로 학습한 attention 패턴이
tabular 피처 간 상호작용에 이전되는지는 논쟁적입니다.

그리고 이 구성을 끝까지 밀면 도착지는 **FT-Transformer**(피처 토큰에 attention)입니다.
우리가 이미 돌린 TabM은 MLP 기반이라 **피처 간 attention이 없고**, PLE 임베딩도
이산 토큰이 아니라 구간 선형(연속)입니다. 즉 **"이산 토큰 + 피처 attention" 칸은 아직 미검증**입니다.

| 구성 | 우리 실측 | 비고 |
|---|---|---|
| TabM (MLP + PLE 연속 임베딩) | 597 | 검증 완료 |
| CatBoost (분기 = 사실상 이산화) | 783 | 현 최고 단일 |
| **이산 토큰 + 피처 attention** | **미측정** | ← 이번 제안이 여는 칸 |
| 사전학습 LLM + 텍스트 직렬화 | 미측정 | 시간·§3 사유로 기각 유지 |

## 5. 실행 설계 (A100)

사전학습 LLM을 쓰지 않는 **from-scratch 이산 토큰 트랜스포머**로 진행합니다
(라이선스·다운로드·시간 리스크가 전부 사라지고, 규칙상 제약도 없음).

1. **토큰화**: 연속형 31개 → train 분위 32bin(경계는 train만으로 산출, pkl 저장).
   범주형 16개 → 값 그대로. 결측 → 컬럼별 전용 `<NA>` 토큰 (cold-start 정보 보존)
2. **모델**: d_model 192~256, 4~6층, 헤드 8. 시퀀스 47(+CLS). 파라미터 3~10M
3. **학습**: BCE, 2019~2023 학습 / 2024 홀드아웃. 시드 3개
4. **추론 예산**: 47토큰 × 24.6만 행 = 1,160만 토큰 → L4에서 분 단위. 여유 충분
5. **채택 기준**: 단독 BSS가 아니라 **현 블렌드(804.70)에 +10 이상 기여**할 때만.
   CatBoost와 표현 방식이 근본적으로 달라 **오차 상관이 낮을 가능성**이 이 실험의 진짜 가치

## 6. 판정

- ❌ **사전학습 LLM + 텍스트 직렬화**: 기각 유지 (시간 3배 초과 + 수치 임계 학습 실패)
- 🟢 **이산 토큰화 + 소형 트랜스포머(from scratch)**: **채택 — 실험 가치 높음**
  - 시간 통과(6.5배 압축), 규칙 리스크 0, 문헌 근거 있음, 캘리브레이션 강점이 Brier와 정합
  - 미검증 칸을 여는 유일한 남은 축
